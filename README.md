# AI-ApiTest：基于 DeepSeek 的接口测试用例生成与失败归因工具

用大模型根据接口规则自动生成测试用例，自动发送请求并断言，再由 AI 分析失败原因，最后输出 Excel 报告。

## 解决什么问题

- 手写接口用例耗时，边界值、异常场景容易漏
- 用例失败后，要人工排查是接口真有缺陷，还是用例本身写错了
- 缺少量化指标，说不清测试到底发现了多少问题

## 功能

- **AI 生成用例**：输入接口规则，DeepSeek 输出 JSON 用例，覆盖正常、边界值、参数缺失、类型错误
- **自动执行**：用 `requests` 发送请求，对比状态码，记录实际结果
- **失败智能归因**：将失败用例分为「接口缺陷」「用例预期不合理」「环境问题」
- **Excel 报告**：汇总指标（通过率、可执行率、缺陷发现率）和用例明细
- **自定义测试要求**：选择接口后输入自己的要求（如"商品数量不能大于10，超出返回400"），AI 据此生成并执行用例
- **自建靶场**：Flask 被测服务，预埋 4 个边界缺陷，用于验证工具的缺陷发现能力

## 流程

```
接口规则 → AI 生成用例(cases.json) → 自动执行(requests) → AI 失败归因 → Excel 报告
```

## 技术栈

Python 3.12、DeepSeek API（OpenAI SDK）、Flask、requests、openpyxl、python-dotenv

## 项目结构

```
AIApiTester/
├── ai_client.py     # DeepSeek 客户端
├── api_spec.py      # 接口规则描述

```

## 快速开始

1. 安装依赖

```
pip install -r requirements.txt
```

2. 配置密钥：复制 `.env.example` 为 `.env`，填入自己的 DeepSeek API Key

```
DEEPSEEK_API_KEY=你的密钥
```

3. 启动被测服务（保持窗口不关）

```
python server.py
```

4. 新开一个终端，运行工具

```
python main.py all
```

## 命令说明

| 命令 | 作用 |
|---|---|
| `python main.py generate` | 只生成用例，保存到 `cases.json` |
| `python main.py run` | 只执行 `cases.json` 中的用例并出报告 |
| `python main.py all` | 生成 + 执行 + 报告（默认） |
| `python main.py custom` | 选择接口，输入自己的测试要求，生成并执行 |

执行后会生成 `results.json`、`测试报告.xlsx`（自定义模式为 `测试报告_自定义.xlsx`）。

## 被测服务与预埋缺陷

`server.py` 提供 4 个接口：登录、查询用户、创建订单、商品列表。其中预埋了 4 个边界缺陷：

1. 密码长度 16 被误拒（应为 6~16 合法）
2. `user_id=0` 未被拦截
3. 下单数量 10 被误拒（应为 1~10 合法）
4. `size=0` 未被拦截

给 AI 的接口规则只描述**正确行为**，缺陷发现率 = 被失败用例命中的预埋缺陷数 / 4。

## 设计要点

- **JSON 模式 + 固定结构**：用 `response_format` 限定 AI 输出，降低解析失败的概率
- **AI 做判断，代码做决策**：早期让 AI 一步给出失败分类，出现过"类别与理由自相矛盾"、多次运行结果不一致的问题。现改为：AI 只回答"预期状态码能否由规则明确推出"，类别由代码按固定规则决定（500 异常或规则明确 → 接口缺陷；规则未写 → 用例预期不合理；请求无响应 → 环境问题）
- **规则不明时不编造**：规则未规定的情况，AI 的预期被标记为"用例预期不合理"，提示补充需求而不是误报缺陷

## 运行结果

两次完整运行（`python main.py all`）的结果：

| 运行 | 用例数 | 通过 | 未通过 | 预埋缺陷发现 | 接口缺陷 | 用例预期不合理 |
|---|---|---|---|---|---|---|
| 第 1 次 | 42 | 33 | 9 | 4/4 | 6 | 3 |
| 第 2 次 | 38 | 30 | 8 | 4/4 | 6 | 2 |

AI 每次生成的用例数量和内容不同，但两次均发现全部 4 个预埋缺陷。首次运行中，除预埋缺陷外，还发现登录接口传入数字类型的用户名/密码时服务返回 500（未做类型校验）。

## 局限与后续计划

- 被测服务为自建小型服务（4 个接口），不代表真实复杂系统
- 目前只断言状态码，尚未校验响应体字段
- 预埋缺陷均为边界值类，后续增加状态码错误、返回字段缺失等类型
- 将执行层迁移到 pytest（参数化、fixture），并接入 GitHub Actions 持续集成
- 增加用例去重与 JSON 结构校验、失败重试
